# `review-repair/v1`

**Status:** current experimental policy

**Use when:** implementation exists; one frozen accepted review question; target
head known; goal is remove blockers under that question.

**Do not use when:** review question missing, false, or still being discovered;
head unknown; work is product/proposal discovery.

Canonical [contract](../../../milestones/README.md) wins. No phase-transition
authority. Apply immutable [shared/v1](../shared/v1.md#shared-definitions).

## Invocation

```text
Follow orchestration policy review-repair/v1 for PR #<number> through final review.
```

## Definitions

```yaml
actors:
  root:
    owns:
      [goal, frozen_question, exact_head, disposition, cycle_decision,
       resume_state, closure]
  reviewer:
    owns:
      [review_one_head, evidenced_findings, repair_proposals,
       approved_repairs_only, focused_validation, anomalies]
    does_not_gain: product_authority

topology:
  live_subordinates_default: 1
  coordinator_default: false
  reviewer_per_cycle: 1          # fresh context
  same_reviewer_for_approved_repair: true
  release_after: review_receipt | repair_receipt
  retain_for: [independent_review, approved_repair, repair_validation]
  do_not_retain_for:
    [cleanup, speculative_improvements, pr_description, integration_supervision,
     ci_waiting, final_acceptance, next_cycle]

sync:
  mechanism: terminal_receipt
  forbidden: [model_polling, progress_prompts, stdin_peeks, sleep_wait_loops]
  clarification_max: 1
  repeated_clarification: redispatch_or_escalate

head:
  bind: exact_sha
  review_receipt_field: head_reviewed
  repair_requires: current_head == head_reviewed
  next_cycle_reviews: head_after
  unexplained_drift: invalidate_receipt

runtime:
  child: lowest_capable_available
  in_policy_economy_tier: sufficient
  tokens_on: reviewed_head
  steering_tokens_on: receipt
  escalate_if:
    [unresolved_uncertainty, missing_capability, lower_tier_failed]
  not_escalate_if: [independent_review_involves_judgment]
  inherit_review_runtime_for_repair: true
  execute_on: child
  runtime_gate:
    terminal_child_result_without_repeated_model_polling: true
    lowest_capable_runtime: <runtime>
  collapse_only_if: not terminal_child_result_without_repeated_model_polling
  gate_fail:
    add_coordinator: false
    max_live_subordinates: 1
    mix_progress_or_repo_inspection_into_waits: false
    record: poll_wait_turns   # policy/runtime failure metric
    label_as_receipt_driven: false

validation:
  one_owner_per_check: true
  rerun_if: [later_change_can_invalidate, final_head_required, contract_requires]

resume_from:
  [pr, head, frozen_question, exact_head_receipts, cycle_ledger, unresolved_findings]
hidden_reviewer_reasoning: not_required

closure:
  owner: root
  no_blocker_receipt_is_final_acceptance: false
  launch_worker_for_closure: false

preconditions_false: stop_and_escalate
```

## Cycle

```text
root --review packet @ exact head--> ONE fresh reviewer (lowest capable runtime)
        |
        | terminal review receipt
        v
root disposition
        |
        +-- findings=[] --> RELEASE --> root closure --> ordinary final acceptance
        |
        +-- address=[...] --> SAME reviewer --repair packet-->
                terminal repair receipt --> RELEASE --> persist ledger
                --> fresh reviewer @ head_after
        |
        +-- escalate --> RELEASE when safe --> stop
```

No-blocker cycle: one dispatch, one receipt, release.
Repair cycle: two interactions with the same child, then release.

## Review dispatch

```yaml
policy: review-repair/v1
cycle: 1
target: {pr: <number>, head: <sha>}
runtime: <lowest capable available runtime>
authority:
  review_question: <frozen question or ref>
  accepted_cases: <accepted matrix or refs>
  review_guidance: <applicable guidance refs>
prior_state: {unresolved_findings: []}
instructions:
  - review this exact head against the frozen question
  - raise only actionable blockers permitted by current review guidance
  - do not broaden the review question
  - do not implement yet
  - for each finding: evidence, contract link, repair shape, validation plan
  - return one dense terminal receipt; raw diffs/logs as refs only
return_schema: [cycle, head_reviewed, findings, escalation_required, evidence_refs]
```

## Repair dispatch and receipt

Requires `current_head == head_reviewed`. Same reviewer context.

```yaml
policy: review-repair/v1
cycle: 1
head_reviewed: abc123
approved_repairs: [RR1]
rejected: []
constraints:
  - implement only approved repairs
  - preserve the frozen review question
  - do not address advisory/rejected observations
  - run focused validation owned by this repair
  - return scope/contract/ownership anomalies instead of absorbing them
  - return one terminal repair receipt
```

```yaml
cycle: 1
head_reviewed: abc123
head_after: def456
findings: {addressed: [RR1], rejected: [], escalated: []}
repair: {completed: [RR1], failed: []}
validation:
  - {check: <focused check>, owner: reviewer, status: pass}
unresolved: []
anomalies: []
next: fresh_review
refs: {diff: <ref>, validation: <ref>, review_receipt: <ref>}
```

Then release the reviewer. If the PR uses `Repair Cycle Ledger`, append the
canonical row (receipt, classification, severity, repair revision, contract
impact).

## Validation

```yaml
validation:
  - {check: focused regression for RR1, owner: reviewer, rerun_at_closure: false}
  - {check: repository-required full suite at final head, owner: root, rerun_at_closure: true}
```

## Closure

After `outcome: no_blockers` on current head:

1. release reviewer
2. verify receipt `head_reviewed` == current head
3. run root-owned final-head validation only
4. persist cycle/ledger state
5. confirm unresolved == []
6. hand off to ordinary exact-head final acceptance

## Complete / escalate

```yaml
complete_when:
  - fresh independent review of current exact head
  - findings: []
  - required_validation: pass
next: ordinary_final_acceptance

escalate_when:
  - accepted_question_false_or_incomplete
  - repair_requires_proposal_amendment
  - safety_schema_ownership_external_or_journey_change
  - validation_contradicts_repair
  - head_drift
  - receipt_not_actionable_after_one_clarification
  - operator_judgment_required
not_escalate_when: additional_cycle_still_permitted_by_contract
```
