​​FOR ROOT INSTANCE TO INITIATE SMALL WORKFLOW. THIS WORKFLOW IS INTENDED FOR SOLUTION SPACE EXPLORATION. NOT FOR IMPLEMENTATION OF CODE. USAGE IS GIVE THIS DOCUMENT TO ORCHESTRATOR, ORCHESTRATOR SPAWNS SINGLE USE HIGH REASONER TO WRITE 3 PROMPTS FROM THIS DOCUMENT, ORCHESTRATOR PROMPT, WORKER PROMPT, PLANNER-GRADER PROMPT USING VOCABULARY (IMPORTANT) FROM THIS DOCUMENT. ORCHESTRATOR NOW EXECUTES (1.) AND (2.) BELOW. INITIATION MUST PROVIDE THESE VALUES OR INFERRABLE BY PROBLEM DESCRIPTION:

{approach} \= the solution space to permutate through  
{conditions} \= where a specific solution is applied  
{artifact description} \= how a verifier reads results as a distillation of computational findings  
{high reasoner} \= model of the planner-grader  
{low reasoner} \= model of the worker

This workflow identifies 3 actors:

* An orchestrator whose job is to relay messages and move the plan forward, very little decision-making power {root agent or low reasoner}  
* A worker who performs the stages of the plan {low reasoner}  
* A reviewer {high reasoner}

The orchestrator must transfer information through references to files which contain artifacts to review instead, reducing chance of summary with {low reasoner} reducing the signal quality of {high reasoner}.

The orchestrator is to persist the {high reasoner} session. This is because the same agent who has the context to generate the plan is the one who grades against the plan continuously.

There is a stop condition where if any stage has been through 5 attempts, the work should stop.

We should define the qualities of a good plan:

* There is a clear expectation of what human reviewer artifact should look like at the end of execution of the entire plan, what verdict is expected  
  * This means the last step of a plan should render a verdict and the reviewer artifact and the verdict should agree. The artifact may disagree with the letter of the verdict. We can find that thresholds are too strict, but the form of the artifact should match the verdict, while being signal dense to a human (a series of simple images over computer readable text).

We should take a step back to determine that unit of work includes planning, but the human should agree with the plan to signal work is to begin, keeping the planner persisted. So the unit of work is two turns/prompt executions, or if we think of the unit of work being tracked two proof of work documents, one by the orchestrator (WORK.log, a strictly informational sequence of what historical thing happened, not details but the event itself, with values for type of event, phase or meta-phase) and one by the planner-grader (PLAN-GRADE.md, a more free-form but sequential document of the happy-path things that happened explaining what intermediate phases concluded, the plan, and the final result):

1. Use a persisted {high reasoner} subagent to create a plan for an experiment in phases. By the end of the experiment we should conclude if {approach} is viable for {conditions} and this conclusion phase should be the last phase. Retain the data that informs the conclusion and render a supporting artifact for inspection in the form of {artifact description}. This plan should not have phase management logic, the phases should be designed such that each phase informs the subsequent phase(s). Write this plan at the top of PLAN-GRADE.md, any changes to the plan should modify this up to start of plan execution, meaning no history of changes, plan is replaced, until execution begins. At the end of change to PLAN-GRADE.md, end the turn for human confirmation of the plan. A log row should be appended to WORK.log for every turn of this step, when the plan is first constructed and every rejection and rewrite.  
2. Execute the plan according to this pattern: have a persisted {low reasoner} subagent act as the worker to execute phases of the plan, up until the last conclusion phase, forking from your orchestrator context. The worker is to execute one phase at a time and once a phase is complete, the subagent is to write a summary of how the phase was executed and files changed, without editorializing against the description of the plan, justifications, into a file. This phase summary file is to be delivered to the planner-grader {high reasoner} subagent to render a pass or a change/re-execute with changes through a separate file from PLAN-GRADE.md, and you as orchestrator will relay this to the worker for retry/rectification. The determination is whether the worker executed to the intent of the plan/planner as well as correctness, by inspection of the changed files. On successful exit of a phase, the {high reasoner} subagent is to commit the summary of phase results to PLAN-GRADE.md. The WORK.log should have a row appended for every worker attempt and review turn and phase transition. The last phase should be completed by the planner-grader {high reasoner} subagent and the conclusion will not be checked. This will be logged in WORK.log, and the conclusion should be appended to PLAN-GRADE.md. If any phase reaches 5 attempt-review cycles, at the end of a 5th review assessing the phase was incompletely returned, the execution of the plan is deemed to be fast-failed. Log this event in WORK.log and the planner-grader should write the assessment of why the phase failed into PLAN-GRADE.md. Following either a fast-fail or end of conclusion phase, that is, in any case, the planner-grader should assess meta-level weakness and strengths of the plan definition itself, given findings throughout the execution of the plan. Where could the plan have been adjusted in terms of phase sizing, valuable artifacts that should’ve been retained, etc. This should have a lens of what should’ve been foreseeable, not to do with the success of the discovery inherent to the work itself, think of the entire process of plan to execution as a trial within trial-and-error itself. This meta-level assessment should be the last section in PLAN-GRADE.md. For this last step, the planner-grader should have access to the WORK.log file. The final row in WORK.log should always be a record of the meta-analysis happening.
