# `product-implementation/v1`

**Status:** experimental; awaiting a real frontier trial.

**Use when:** operator-assigned implementation of one accepted frontier proposal.
The proposal fixes acceptance, not every implementation choice.

**Do not use when:** no accepted proposal; proposal/amendment still in review;
idle current; product discovery; independent review, acceptance, merge, or
closeout.

Canonical [contract](../../../milestones/README.md) wins. No phase-transition
or acceptance authority. Apply immutable
[shared/v1](../shared/v1.md#shared-definitions). Overrides below win over
shared defaults for this policy only.

## Invocation

```text
Follow orchestration policy product-implementation/v1 to implement
<accepted proposal> on <milestone branch>. Deliver ready for independent review.
```

## Flow

```text
accepted proposal + recorded workflow state
      v
ONE root compiles packet
      v
ONE worker: complete slice @ lowest capable runtime
      v
terminal receipt
      |
plan/contract fit? --mechanics fail--> root recompiles --> redispatch
      |
      |-- contract change --> canonical escalation
      v
    matched
      |
work remains? --yes--> next unit
      v
root Z1 closure --> ready for independent review
```

## Decision routing

| Observation | Owner / next action |
| --- | --- |
| Algorithm, layout, or internal choice left open | Worker chooses within constraints; validate public behavior; record material decision. |
| Pattern fails; accepted outcome/owner hold | Root revises affected unit, records failed assumption, redispatches. |
| Another file needed within accepted owner/behavior | Worker reports path/reason; root reconciles packet. File drift alone is not contract drift. |
| Question, non-goal, safety/authority, schema, assumption, owner, criterion, or handoff must change | Stop dependent work; canonical amendment/later-frontier route. |
| Human requests additive behavior during testing | Canonical HITL classification; no automatic adjunct authorization. |
| External capability missing | Identify owner/minimum contract; canonical capability-gap route. |

Accepted product details stay binding. More reasoning grants no authority.

## Child dispatch / receipt

Child gets the compiled unit, accepted pattern if applicable, owned source
refs, validation owner, and escalation boundaries.

```yaml
policy: product-implementation/v1
packet_revision: 1
unit: A1
runtime: <lowest capable available runtime>
pattern: <pattern-id or null>
constraints: [<must preserve>]
validation:
  - {check: <focused check>, owner: A1}
escalate_if:
  - pattern does not apply cleanly
  - another owner/boundary appears
  - accepted contract must change
  - validation exposes an unpredicted failure class
return_schema:
  [unit, packet_revision, input_head, head_after, status, plan_fit,
   changed_paths, decisions, validation, unresolved, anomalies, next]
```

```yaml
unit: A1
packet_revision: 1
input_head: <sha>
head_after: <sha>
status: complete # or anomaly / failed
plan_fit: matched
changed_paths: []
decisions: [] # choice, preserved constraint, evidence; material decisions only
validation: [{check: <identity>, revision: <sha>, result: pass, evidence: <ref>}]
unresolved: []
anomalies: []
next: <remaining unit or root closure>
```

Lifecycle: `dispatch once -> terminal receipt once -> release child`.
A completion receipt is not independent review or acceptance.

## Validation / QCA

```yaml
validation:
  one_owner_per_check: true
  focus: accepted_consumer_and_boundary_behavior
  mechanism_tests: justify_when_needed
  rerun_if: [relevant_input_changed, final_head_required, concrete_concern]
  record: [command, revision, outcome, limitations, evidence_ref]
  stale_pass_as_new_evidence: false
qca:
  use_when: existing_target_revision_capability_is_useful
  contract_observation: inspect_consumer_compatibility
  test_effectiveness_candidate: inspect_exercised_boundary
  material_result: decision_and_evidence_in_receipt
  not_authority: [missing_evidence, static_candidate, count]
  not_required: [run, score, new_detector, deletion, gate]
  replaces_accepted_tests_or_product_evidence: false
```

## Z1 closure

1. reconcile completed units, paths, decisions, and anomalies to the proposal
   and amendments
2. finish scoped integration; verify integrated/final-head checks and evidence
3. create/update the implementation PR with the canonical template, exact
   validation, limitations, proposal references, and real repair history;
   batch metadata where possible
4. persist the run outcome; hand off ready for independent review

## Complete / escalate

```yaml
complete_when:
  - accepted_scope_delivered
  - required_validation pass on final head
  - evidence_obligations_met
  - unresolved_anomalies: []
  - implementation_pr_accurate
  - handoff_recorded
next: independent_implementation_review
not_authorized:
  [self_acceptance, merge, milestone_completion, frontier_advance,
   automatic_review_loop]
explicitly_composed_review:
  requires: ordinary_role_and_phase_assignment
  packet: fresh_exact_head_same_accepted_question
escalate_when:
  - accepted_question_or_contract_must_change
  - safety_schema_ownership_external_or_handoff_change
  - human_additive_request_needs_HITL_classification
  - missing_external_capability
  - receipt_not_actionable_after_one_clarification
  - operator_judgment_required
```
